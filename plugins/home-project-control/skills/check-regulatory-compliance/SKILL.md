# Нормативное соответствие

## Входной контроль

До анализа выполнить [протокол рабочей папки](../../references/workspace-protocol.md). Продолжать только при `existing_project_ready` и `gate_passed: true`; иначе передать создание или восстановление проводнику. Факты проекта брать только из полностью прочитанных точных версий и зарегистрированных источников по [онтологии](../../references/ontology.md).

Для объекта, зоны, системы и оборудования применять [модель физического объекта](../../references/physical-object-model.md). Нормативная проверка не заменяет проектирование, расчёт, обследование, измерение, испытание или заключение компетентного специалиста.

## Назначение

Разделять четыре разных вопроса:

1. действует ли точная редакция документа на дату проверки;
2. применимо ли конкретное требование к этому объекту, этапу, решению и договорному контексту;
3. достаточно ли доказательств для проверки;
4. соответствует ли проверяемое решение конкретному пункту.

Название документа или его статус сами по себе не доказывают применимость и соответствие.

## Порядок проверки

1. Зафиксировать юрисдикцию, территорию, тип объекта, дату проектирования или вмешательства, этап жизненного цикла, проверяемые `ProjectPackage`, `Site`, `Zone`, `System`, `Asset`, КП, работу или задание.
2. Определить затронутые профессиональные направления и опасные последствия. Не составлять универсальный список норм без связи с предметом проверки.
3. Найти потенциальные документы только по официальным источникам из [политики источников РФ](references/ru-source-policy.md) либо по иной подтверждённой юрисдикции.
4. Для каждого `NormReference` проверить обозначение, точное название, редакцию, статус, замену, дату проверки, территорию, официальный источник статуса и законно доступный текст.
5. Отдельно установить основание применимости каждого пункта: обязательное требование, принятое проектом, включённое договором, справочное либо неприменимое. Не считать добровольность документа универсальным свойством для любого контекста.
6. Извлечь только нужные атомарные `RegulatoryRequirement` с точным локатором, условиями применения, способом проверки и границей профильной компетенции. Не копировать полный текст нормативного документа в плагин или проект без подтверждённого права использования.
7. Для каждого требования создать `ComplianceResult`: объект проверки, статус применимости, статус соответствия, доказательства, находки, пробелы и дату.
8. Завершать `ComplianceAssessment` только при покрытии каждого заявленного требования ровно одним результатом. Отсутствие данных блокирует зависимый пункт, а не остальные проверки.
9. Показать отдельно: подтверждённое соответствие, частичное соответствие, конфликт, непроверенное, неприменимое и требующее специалиста.

Подробные поля и критерии описаны в [методике нормативной проверки](references/regulatory-method.md).

## Связь с другими процессами

- При анализе КП передавать идентификатор завершённой оценки в `review-contractor-proposal`; обязательный нормативный пункт не закрывается общей ссылкой на ГОСТ или СП.
- При подготовке задания включать только применимые требования с редакциями, пунктами, способом подтверждения и формой результата.
- При приёмке преобразовывать требования в измеримые критерии, документы, испытания и точки контроля.
- При эксплуатации и вмешательстве проверять требования безопасности, совместимости, обслуживания и допустимости работ для точной локации и системы.
- Нормативные трудозатраты, рыночную цену и фактическую практику хранить раздельно.

## Запись

Собрать JSON-пакет версии `1.0` с разделами `norm_references`, `regulatory_requirements`, `compliance_assessments`, `compliance_results` и при необходимости `regulatory_sync_runs`. Сначала выполнить:

```text
python scripts/record_regulatory_assessment.py <папка-проекта> <regulatory-package.json>
```

Запись выполнять только после отдельного подтверждения повторным запуском с `--apply`. Утилита сохраняет историю и откатывает весь пакет, если он добавляет предупреждение аудита.

## Контроль обновлений

`scripts/check_regulatory_updates.py` сравнивает официальные страницы со снимком источников и создаёт отчёт об изменениях. Изменившийся отпечаток страницы является только сигналом для повторной проверки; утилита не меняет редакцию, применимость, результат соответствия или предыдущий отчёт автоматически.

Перед каждым значимым нормативным выводом перепроверять применимые документы в официальном источнике независимо от периодического мониторинга. Если официальный текст недоступен, статус документа и содержание требования считать разными уровнями подтверждения и явно ограничить вывод.
