# Сравнение проектов

## Входной контроль проекта

До чтения документов вызвать `inspect_project_workspace` с точным путём текущей рабочей папки. При `existing_project_ready` продолжить без вопросов. Иначе открыть `open_project_setup_form` и не начинать профильную работу до `gatePassed: true`; создание и восстановление структуры передать проводнику проекта. При смене папки проверить её заново.

## Интерактивные вопросы

Когда пользователь выбирает один или несколько готовых вариантов, вызывать `open_choice_form`: `single` для одного ответа, `multiple` для нескольких. Свободный текст оставлять для уникальных фактов и пояснений. Выбор считать подтверждённым только после `submit_choice_form` с `accepted: true`; если форма недоступна, дать короткие нумерованные варианты в чате.

## Допуск аналога

Не включать пример в расчёт автоматически. Сначала показать источник, дату и отличия, затем получить от пользователя подтверждение релевантности. Зафиксировать решение в `.home-control/comparables.jsonl`.

## Проверка сопоставимости

Сравнить регион и дату цены, тип и состояние объекта, площадь и единицы измерения, состав работ, уровень материалов, налоги, доставку, монтаж, условия площадки и качество доказательств фактической стоимости.

Если ключевое различие не удаётся нормализовать, показывать проекты рядом, но не использовать их для численного вывода.

## Нормализация

- Приводить объёмы к одинаковой единице только при однозначном пересчёте.
- Не обновлять старую цену инфляцией без согласованного индекса, периода и источника.
- Не конвертировать валюту без согласованной даты и курса.
- Не считать среднее по несопоставимым объектам.
- Показывать диапазон исходных подтверждённых значений и каждую корректировку отдельно.

Для каждого аналога оценивать не «качество проекта вообще», а пригодность к конкретному выводу: цена материала, ставка работ, длительность, конструктивное решение или полный бюджет. Один и тот же аналог может быть пригоден для одного показателя и непригоден для другого.

Не скрывать размер выборки. При одном или двух аналогах описывать наблюдения, а не статистический рынок. Не назначать веса и доверительные интервалы без достаточной методики и данных.

## Заключение

Разделить подтверждённые данные текущего проекта, подтверждённые данные аналогов, корректировки, оставшиеся различия, допустимый вывод и решения, которые данные принять не позволяют. Не называть ориентир рыночной ценой, если выборка не подтверждает рынок.

Для каждого численного ориентира указывать число использованных аналогов, минимум, максимум, единицу, дату цены, корректировки и ограничения применимости.

Для регистрации использовать [comparable-template.md](references/comparable-template.md).
