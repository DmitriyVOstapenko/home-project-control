# Задание для подрядчиков

## Входной контроль проекта

До чтения документов выполнить [протокол рабочей папки](../../references/workspace-protocol.md). Продолжать только при `existing_project_ready` и `gate_passed: true`; иначе передать создание или восстановление проводнику. Каждый анализируемый документ читать по точной версии с [контролем покрытия](../../references/document-reading.md), а утверждения классифицировать по [общей онтологии](../../references/ontology.md). При смене папки проверить её заново.

Если задание касается действующего объекта или оборудования, использовать [модель физического объекта](../../references/physical-object-model.md).

## Интерактивные вопросы

Задавать вопросы в чате небольшими блоками. Для закрытых вопросов давать короткие нумерованные варианты; свободный текст оставлять для уникальных фактов. Ответ не заменяет отдельного согласия на запись или внешнее действие.

## Цель

Создать единый пакет, чтобы различия в ответах отражали реальные различия цены и решения, а не разные трактовки задания. Не проектировать отсутствующее техническое решение и не подменять проектировщика.

## Подготовка

1. Зафиксировать объект, локации, затрагиваемые установленные `Asset`, версию исходных документов и предмет запроса.
2. Разделить обязательный объём, опции и работы вне запроса.
3. Описать результат каждой работы и доступные количества.
4. Указать неизвестные данные как запрос на обследование или отдельную расценку.
5. Определить ответственность за материалы, доставку, разгрузку, хранение, временную защиту и уборку.
6. Задать одинаковую форму цены, единицы, налоги, сроки действия и условия пересмотра.
7. Потребовать явный перечень исключений, допущений и замен.
8. Указать контрольные точки, документы качества, исполнительные материалы, гарантию и условия приёмки.
9. Для действующего объекта определить допустимый простой, временное решение, сохранение данных и конфигурации, порядок отключения, миграции, пусконаладки и возврата к исходному состоянию.

## Поиск кандидатов

Если пользователю нужен список подрядчиков, выполнить актуальный поиск по тому же предмету, территории и применимому типу объекта. Для каждого кандидата сохранить поисковый запрос, дату, прямой источник, доступные подтверждения специализации и сведения, которые ещё нужно запросить.

Не ранжировать кандидатов только по рейтингу или отзывам и не утверждать квалификацию без подтверждения. Список является воронкой для одинакового запроса, а не выбором подрядчика. Пользователь решает, кому направлять задание; не обращаться к организациям без отдельного разрешения.

## Защита сопоставимости

- Не просить подрядчика включить «всё необходимое» без раскрытия состава.
- Не смешивать базовый объём и улучшения в одной неразделённой цене.
- Не принимать строку «комплект» без состава, количества и характеристик.
- Не требовать фиксированную цену для неизвестного объёма без механизма его измерения.
- Не добавлять нормативное требование без применимого источника и версии.

## Результат

Сформировать пакет по [brief-template.md](references/brief-template.md): список кандидатов и журнал поиска, письмо-запрос, описание объекта, матрицу объёма, форму цены, форму отклонений, вопросы, состав закрывающих документов и правила представления альтернатив.

Сохранить согласованную версию в папке `03_Коммерческие_предложения` или другой подтверждённой папке проекта. До записи показать имя файла и не заменять существующую версию.
