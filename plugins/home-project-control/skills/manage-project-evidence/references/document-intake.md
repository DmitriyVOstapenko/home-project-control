# Приём новых документов

Этот сценарий применяется, когда пользователь прикрепил файлы к сообщению или указал другие файлы вне папки проекта.

## Разделение слоёв

- Вложение или внешний файл — входной материал, а не постоянное хранилище проекта.
- Копия в одной из управляемых папок — локальный оригинал, с которым дальше работает плагин.
- `documents.json` хранит индекс версий и непроверенное описание, данное пользователем.
- Конспекты, извлечённые факты и прочие служебные данные хранятся в `.home-control` и не подменяют оригинал.

## Порядок приёма

1. Проверить gate проекта.
2. Для каждого файла зафиксировать данное пользователем описание и предложить предполагаемую роль. Если статус или область невозможно установить без чтения, пометить их как непроверенные; не задерживать весь пакет вопросами, которые можно закрыть после чтения.
3. Сопоставить каждый файл с ровно одной папкой из `schemas/project-structure.json`. Не создавать новые разделы без отдельного решения.
4. Для разнородного пакета создать временный manifest вне папки оригиналов:

   ```json
   {
     "schema_version": "1.0",
     "batch_description": "Первичный пакет документов объекта",
     "items": [
       {
         "source": "C:/путь/Проект.pdf",
         "target_folder": "02_Проекты_и_технические_решения",
         "description": "Проектное решение; статус предстоит проверить"
       },
       {
         "source": "C:/путь/КП.xlsx",
         "target_folder": "03_Коммерческие_предложения",
         "description": "Коммерческое предложение подрядчика"
       }
     ]
   }
   ```

5. Выбрать доступный Python 3, разрешить `scripts/ingest_documents.py` относительно каталога установленного скилла и выполнить один предварительный запуск:

   ```text
   python scripts/ingest_documents.py <папка-проекта> --manifest <intake.json>
   ```

6. Показать пользователю единый понятный план `исходное имя → папка/имя`, описания, совпадения и будущую запись `DocumentIntakeBatch`.
7. После одного явного согласия на весь показанный пакет повторить команду с `--apply --expected-batch-id <ID из предварительного плана>`. Если файл изменился после показа, идентификатор не совпадёт и запись будет заблокирована.
8. После приёма перейти к полному чтению и конспекту; уточнять только конфликты, критичные пробелы и решения владельца.

Для одного или нескольких файлов с одинаковыми описанием и целевой папкой сохраняется сокращённый режим `--source ... --target-folder ... --description ...`.

## Границы автоматизации

- Утилита копирует, но не перемещает и не удаляет исходный файл.
- Предварительный запуск ничего не записывает. `--apply` атомарно копирует весь пакет, проверяет SHA-256, обновляет индекс, добавляет контекст приёма и одну запись `DocumentIntakeBatch`. При ошибке служебные реестры и уже созданные копии откатываются.
- Если в целевой папке уже есть файл с тем же SHA-256, дубликат не создаётся. Контекст приёма добавляется к уже существующей записи.
- Если имя занято файлом с другим содержимым, запись блокируется. Новое имя задаётся только после его показа и согласования.
- Описание приёма статусом `unreviewed` фиксирует, как пользователь представил файл, но не доказывает его содержание или статус.
