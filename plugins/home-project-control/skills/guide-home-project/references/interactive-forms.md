# Интерактивные формы

## Автоматическая проверка и мастер проекта

При первом обращении к плагину в новой задаче вызвать `inspect_project_workspace` с точным абсолютным путём текущей рабочей папки. Инструмент без вопросов проверяет карточку проекта, привязку пути, обязательные папки, наличие служебных файлов и их базовый формат.

Если получены `status: existing_project_ready` и `gatePassed: true`, не показывать стартовую форму. Продолжить работу в существующем проекте.

Во всех остальных случаях вызвать `open_project_setup_form`. Мастер позволяет:

- указать папку существующего проекта;
- задать название и полный путь нового проекта;
- восстановить только недостающие элементы текущего распознанного проекта.

Результат `submit_project_setup` считать подтверждением выбранного действия. Для создания или восстановления выполнить неразрушающий сценарий `init_project.py --dry-run`, затем создать только отсутствующие элементы и вызвать `verify_project_context`. Не читать документы и не запускать профильный анализ до `gatePassed: true`.

Проверка относится к рабочей папке, которую клиент передал Codex. Не утверждать, что проверена принадлежность отдельному визуальному контейнеру «Проект» в интерфейсе ChatGPT, если такого поля нет в доступном контексте.

## Основная анкета

Вызывать `open_project_intake_form` только после успешной стартовой проверки, когда пользователь:

- начинает новый проект;
- продолжает проект из существующей папки;
- проверяет дом или квартиру перед покупкой;
- ещё не определил системы и виды работ;
- просит вести его по шагам.

Форма собирает только ответы и не создаёт проектную папку. После `submit_project_intake`:

1. кратко повторить подтверждённые пункты;
2. отдельно перечислить неизвестное;
3. задать один следующий вопрос, который нельзя заменить готовым вариантом;
4. если нужна папка, запросить или предложить полный путь и выполнить обычную процедуру сухой проверки и отдельного согласия.

## Когда нужен текст

Текстовый ответ нужен для уникальных фактов, которых нет в закрытом перечне: точного пути, названия объекта, местоположения, конкретного ограничения, состава приложенного документа или формулировки цели. Не просить пользователя повторно печатать то, что уже подтверждено через форму.

## Последующие вопросы

Для закрытых вопросов после основной анкеты вызывать `open_choice_form`. Тип `single` использовать, когда допустим только один ответ; тип `multiple` — когда можно выбрать несколько. Передавать от двух до двадцати коротких, взаимоисключающих или совместимых вариантов и не более шести связанных вопросов за один раз.

Вариант «не знаю» добавлять, если пользователь действительно может не располагать данными. Не добавлять вариант от себя как подтверждённый ответ. Результат считать подтверждённым только после `submit_choice_form` с `accepted: true`.

## Резервный режим

Если интерфейс не отобразился, сначала выполнить ту же автоматическую проверку. При исправном проекте продолжить без вопросов. Иначе текстом предложить выбрать существующую папку или создать новый проект, запросив название и путь только для создания. После успешной проверки задать остальные вопросы небольшими блоками.
