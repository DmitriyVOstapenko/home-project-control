# Рабочие режимы эксплуатации

Использовать только применимый режим. Общая единица работы — конкретный запрос владельца, связанный с подтверждённой локацией и затрагиваемыми установленными активами.

## Карточка запроса

Зафиксировать:

- желаемый результат и инициатора;
- `Site`, применимая `Zone` и точность определения места;
- затрагиваемые `Asset` и известные связи;
- текущее состояние и доказательства;
- неизвестные данные и конфликтующие источники;
- ограничения эксплуатации, доступа, безопасности и допустимого простоя;
- критерии сравнения вариантов;
- требуемое решение владельца.

После согласия на запись оформить карточку как `WorkRequest`. Наблюдения состояния связывать с `ConditionAssessment`; будущие действия не записывать как произошедший `AssetEvent`.

## Режим A. Локальное изменение

1. Описать геометрию вмешательства: точку или зону, направление, глубину и инструмент, если они известны.
2. Поднять планы, исполнительные схемы, фотографии до закрытия, сведения о слоях и скрытых системах.
3. Проверить, совпадает ли документ с фактической редакцией объекта и нужной локацией.
4. Перечислить подтверждённые препятствия и отдельно неизвестные трассы или слои.
5. Определить необходимое обследование, проектное решение, отключение или профильного специалиста.
6. После выполнения получить фиксацию фактического положения и обновить историю объекта.

## Режим B. Обслуживание или неисправность

1. Отделить наблюдаемый симптом от предполагаемой причины.
2. Зафиксировать время, режим работы, показания, сообщения системы и затронутую функцию.
3. Проверить регламент, гарантию, предыдущие события и выполненные ранее вмешательства.
4. Определить дистанционно проверяемые данные и то, что требует измерения или специалиста на месте.
5. Сравнить допустимые действия по результату, риску простоя, стоимости и влиянию на другие активы.
6. Не объявлять причину установленной без достаточного доказательства.

## Режим C. Ремонт, модернизация или замена

Сравнить как отдельные варианты:

| Критерий | Продолжить обслуживание | Ремонт | Частичная модернизация | Замена |
|---|---|---|---|---|
| Восстанавливаемая функция | | | | |
| Подтверждённая стоимость | | | | |
| Простой и временное решение | | | | |
| Совместимость и зависимости | | | | |
| Сервис, запчасти и поддержка | | | | |
| Риски и неизвестные данные | | | | |
| Горизонт сравнения | | | | |

Возраст использовать только как одно из подтверждённых свойств. Решение о замене обосновывать состоянием, функцией, риском, экономикой и доступностью поддержки на согласованном горизонте. Расчёт вариантов хранить как `LifecycleCostAssessment`, аналитический вывод — как `LifecycleDecision`, а разрешение владельца — отдельно как `OwnerDecision`.

## Режим D. Несколько локаций

Не считать одинаковые модели доказательством одинаковых условий. Для каждой локации проверить монтаж, питание, сеть, нагрузку, интеграции, среду, доступ и допустимый простой. Выделить пилот, условия успешности, последовательность развёртывания, резервный сценарий и фиксацию результата по каждому установленному экземпляру.

## Внешние кандидаты

Для поставщика или подрядчика сохранять поисковый запрос, дату, территорию, прямой источник, доступные подтверждения специализации и то, что ещё нужно запросить. Статус кандидата не является рекомендацией или решением о контакте.
