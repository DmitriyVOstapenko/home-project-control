# Планирование проекта дома

## Входной контроль проекта

До чтения документов вызвать `inspect_project_workspace` с точным путём текущей рабочей папки. При `existing_project_ready` продолжить без вопросов. Иначе открыть `open_project_setup_form` и не начинать профильную работу до `gatePassed: true`; создание и восстановление структуры передать проводнику проекта. При смене папки проверить её заново.

## Интерактивные вопросы

Когда пользователь выбирает один или несколько готовых вариантов, вызывать `open_choice_form`: `single` для одного ответа, `multiple` для нескольких. Свободный текст оставлять для уникальных фактов и пояснений. Выбор считать подтверждённым только после `submit_choice_form` с `accepted: true`; если форма недоступна, дать короткие нумерованные варианты в чате.

## Основание плана

Сначала прочитать паспорт проекта, выбранные системы, проекты, обмеры, ограничения и договорные даты. Если данных недостаточно, построить структуру этапов без календарных дат и пометить неизвестные продолжительности.

Не считать типовую последовательность обязательной для конкретного объекта. Противоречия между проектами, фактическим состоянием и пожеланиями вывести до планирования.

## Порядок

1. Определить конечные результаты и границы проекта.
2. Разбить их на проверяемые элементы работ с владельцем результата.
3. Зафиксировать входы, зависимости и то, что блокирует начало каждого элемента.
4. Определить точки решения владельца и точки проверки до скрытия работ.
5. Связать закупки с утверждением проекта, обмерами, сроком поставки, хранением и монтажом.
6. Добавлять даты только из подтверждённых обязательств либо согласованного пользователем сценария.
7. Проверить коллизии между системами и ответственность за стыки подрядчиков.
8. Сохранить согласованные элементы в `work_items.csv`, а закупочные события — в `procurement.csv`.

## Сценарии вместо ложной точности

Если продолжительности или ресурсы неизвестны, показывать:

- подтверждённые даты;
- расчётные даты с формулой и основанием;
- условные сценарии;
- события без даты;
- данные, которые нужно получить у подрядчика.

Не выводить критический путь, пока зависимости и длительности не подтверждены в достаточной степени.

## Результат

Использовать структуру из [planning-framework.md](references/planning-framework.md). Отдельно показать ближайшие решения, зависимые закупки, точки приёмки, риски стыков и элементы, которые пока нельзя календарно планировать.
