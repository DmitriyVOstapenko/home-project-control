# Реестры договора и изменений

## Изменение

| Поле | Содержание |
|---|---|
| `change_id` | Устойчивый ID |
| Дата и инициатор | По подтверждённому источнику |
| Исходный объём | Ссылка на обязательство или строку сметы |
| Локации и активы | Где действует изменение и какие `Asset` затронуты |
| Предлагаемое изменение | Измеримый новый результат |
| Причина | Документированная либо заявленная стороной |
| Цена и валюта | Разница и способ расчёта |
| Влияние на срок | Подтверждённое или неизвестное |
| Влияние на другие работы | Связи и коллизии |
| Влияние на эксплуатацию | Простой, временное решение, поддержка, данные и конфигурация |
| Статус | Только допустимое значение |
| Решение владельца | ID решения и дата |
| Документы | Предложение, согласование, акт |

## Обязательство

| Поле | Содержание |
|---|---|
| `commitment_id` | Устойчивый ID |
| Сторона | Кто должен выполнить или предоставить |
| Результат | Измеримое обязательство |
| Локации и активы | Область действия обязательства |
| Срок или событие | Как записано в источнике |
| Основание | Документ и локатор |
| Статус | `open`, `due`, `claimed_complete`, `verified`, `waived`, `disputed`, `superseded` |
| Доказательство закрытия | Документ и локатор |

Не преобразовывать неоднозначное условие в однозначную дату без отдельного основания.

Для сервисного обязательства отдельно фиксировать измеримый регламент, событие обращения, срок реакции или восстановления, исключения, требуемое доказательство и условия закрытия. Не придумывать уровень сервиса, если договор его не задаёт.
