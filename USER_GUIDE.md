# Как пользоваться «Контролем дома»

«Контроль дома» помогает владельцу, покупателю или управляющему разбирать документы по дому или квартире, оценивать коммерческие предложения, выбирать материалы и оборудование, контролировать работы, расходы и эксплуатацию.

Репозиторий продукта:

<https://github.com/DmitriyVOstapenko/home-project-control>

## Что это такое

«Контроль дома» — устанавливаемый плагин для Codex и Claude Code.

Это не отдельная модель искусственного интеллекта и не самостоятельный агент. Агентом остаётся Codex или Claude Code. Плагин добавляет агенту:

- 14 специализированных скиллов — инструкций для повторяемых рабочих процессов;
- общую модель данных дома, квартиры, систем, оборудования, документов, требований и решений;
- правила доказательной работы с источниками;
- локальные Python-утилиты для структуры проекта, версий документов, аудита и отчётов.

Пользователю не нужно выбирать скилл вручную: достаточно описать задачу обычными словами. Агент должен определить подходящий рабочий процесс. В Claude Code при необходимости скилл можно вызвать явно командой `/home-project-control:<имя-скилла>`.

## Быстрая установка

### Codex

```text
codex plugin marketplace add DmitriyVOstapenko/home-project-control --ref main
codex plugin add home-project-control@home-project-control-marketplace
```

После установки откройте новую задачу Codex.

### Claude Code

```text
claude plugin marketplace add https://github.com/DmitriyVOstapenko/home-project-control.git
claude plugin install home-project-control@home-project-control-marketplace
```

После установки начните новую сессию или выполните `/reload-plugins`, если Claude Code предложит это.

Подробные варианты установки и удаления находятся в [INSTALL.md](INSTALL.md).

## Как обновлять

### Codex

```text
codex plugin marketplace upgrade home-project-control-marketplace
codex plugin add home-project-control@home-project-control-marketplace
```

После обновления начните новую задачу Codex: уже открытая задача может продолжать использовать прежнюю версию скиллов.

### Claude Code

```text
claude plugin marketplace update home-project-control-marketplace
claude plugin update home-project-control@home-project-control-marketplace
```

После обновления выполните `/reload-plugins`, если это требуется клиентом.

## Как организовать проект

Плагин устанавливается один раз. Для каждого дома, квартиры или группы связанных объектов создаётся отдельная папка проекта вне репозитория плагина.

Пример:

```text
Мои проекты/
└── Дом в Подмосковье/
```

Откройте эту папку как рабочую папку новой задачи Codex или сессии Claude Code. Не копируйте проектные документы в репозиторий `home-project-control`.

Первое сообщение:

```text
Веди меня по новому проекту дома. Сначала проверь текущую папку, покажи план создаваемой структуры и ничего не записывай без моего подтверждения.
```

После подтверждения плагин создаст служебную папку `.home-control` и тематические каталоги внутри пользовательского проекта. Один экземпляр установленного плагина может по очереди работать с разными папками проектов.

## Как передавать документы

Документы можно прикреплять к сообщению. Вместе с файлами укажите:

- что это за документ;
- к какому объекту, помещению, системе или этапу он относится;
- является ли он утверждённым документом, черновиком, коммерческим предложением, договором, актом, счётом или фотографией;
- известную дату и версию;
- что именно требуется получить.

Пример:

```text
Прикрепляю утверждённый проект электроснабжения от 12 мая 2026 года и черновик изменений. Они относятся к дому на участке № 15. Покажи, куда предлагаешь поместить каждый файл, но ничего не копируй без моего подтверждения. Затем проиндексируй и полностью прочитай утверждённую версию с чек-листом покрытия.
```

Плагин не должен изменять оригиналы. Сначала он показывает план приёма, а после подтверждения копирует документы в тематические папки, индексирует точную версию и сохраняет контрольную сумму.

## По какой логике работает продукт

Работа строится последовательно:

1. Проверяется точная рабочая папка и готовность структуры проекта.
2. Документы классифицируются и принимаются без изменения оригиналов.
3. Для каждой точной версии независимо выявляются страницы, листы, изображения, формулы, приложения и другие единицы чтения.
4. Документ читается по чек-листу физического покрытия; пробелы и неразборчивые места фиксируются, а содержание конспектируется в Markdown.
5. Отдельный проверяемый запуск проходит смысловые разделы и извлекает атомарные факты, требования, конфликты и недостающие данные с точными локаторами.
6. Факты связываются с одной или несколькими дисциплинами и пакетами проекта. Оригинал документа хранится один раз, даже если относится одновременно к ОВиК, электрике и архитектуре.
7. Перед первым выводом о соответствии КП владелец отдельно принимает базовую линию из выбранных полностью прочитанных версий документов.
8. Коммерческое предложение не включается в базовую линию. Без принятой базы независимые проверки КП продолжаются, но справочное сравнение не выдаётся за подтверждённое соответствие проекту.
9. Недостающая информация блокирует только конкретные зависимые выводы. После ответа продукт повторяет именно их, а не весь анализ.
10. Пакеты проверяются между собой: учитываются общая электрическая мощность, физическое место, трассы, конструкции, дренаж, сеть, сервисный доступ и последовательность работ.
11. Для конкретной задачи выбираются один или несколько профессиональных процессов: архитекторский, инженерный, сметный, закупочный, договорный, прорабский или эксплуатационный.
12. Нормативная проверка отделяет актуальный статус документа от его применимости к объекту и от фактического соответствия решения; каждый вывод привязывается к точному пункту и доказательствам.
13. Выводы связываются с точными источниками. Для ЛПР сначала формируется короткая карточка решения, а полное досье начинается тем же каноническим резюме.
14. Любая запись в структуру проекта сначала показывается как план и выполняется только после подтверждения владельца.

## Готовые примеры запросов

### Полный аудит коммерческого предложения

```text
Прикрепляю коммерческое предложение подрядчика. Выполни полный профессиональный аудит по всем затронутым направлениям.

Сначала проверь, существует ли принятая мной базовая линия проекта. Если её нет, покажи полностью прочитанные документы-кандидаты, их точные версии, роль, область применения и конфликты и запроси моё решение. Само КП в базовую линию не включай.

Прочитай каждую страницу, таблицу, примечание и приложение КП. После проверки физического покрытия отдельно пройди все смысловые разделы, извлеки атомарные факты с локаторами и зарегистрируй недостающие данные. Отнеси КП и факты к применимым дисциплинам и пакетам проекта, не копируя оригинал документа.

Проверь полноту, объёмы, арифметику, цены, техническое решение, совместимость с проектом, интерфейсы, исключения, сроки, оплату, гарантию, пусконаладку, приёмку и эксплуатационные последствия. Если затронуты другие пакеты, проверь конкуренцию за мощность, пространство, трассы, конструкции, дренаж, сеть, доступ и последовательность. Отсутствующая информация должна блокировать только зависимые выводы.

Определи применимые нормативные документы по официальным источникам. Для каждого проверенного требования укажи точную редакцию и пункт, условия применимости, объект проверки, доказательства и результат. Отдельно покажи требования проекта и договора, справочные ориентиры и границу обязательной проверки профильным специалистом. Не делай вывод о соответствии только по названию документа.

Покажи сильные и слабые стороны, отсутствующие данные, вопросы подрядчику, риски и полную возможную стоимость. Предложи улучшение исходного решения, сопоставимый вариант того же класса, иной технический принцип и вариант ремонта, отсрочки или отказа от вмешательства, если он применим.

Найди актуальные сопоставимые цены и альтернативных подрядчиков с прямыми ссылками, датой, регионом и ограничениями сравнения. Заверши короткой карточкой ЛПР с точным вопросом ко мне, тремя главными рисками и условиями, предпочтительной альтернативой или обоснованием отсутствия выбора; поставь тот же блок в начало полного досье. Добавь прорабский вердикт, условия до договора, план проверки работ и измеримой приёмки. Ничего не записывай без моего подтверждения.
```

### Подбор оборудования

```text
Нужно подобрать оборудование для указанной системы и зоны. Сначала извлеки из проекта точные требования и ограничения. Затем сравни не менее трёх реально доступных вариантов по совместимости, производительности, монтажу, обслуживанию, гарантии, доступности запчастей, цене и полной стоимости владения. Сошлись на актуальные источники и отдели подтверждённые характеристики от рекламных утверждений.
```

### Приёмка работ перед оплатой

```text
Подрядчик предъявил этап к оплате. Сопоставь выполненное с проектом, договором, сметой и согласованными изменениями. Подготовь чек-лист визуальной и инструментальной проверки, испытаний, исполнительных документов и критериев приёмки. Отдельно покажи, что нельзя подтвердить по документам и фотографиям и должен проверить профильный специалист на объекте.
```

### Изменение в готовом доме

```text
Я хочу выполнить это изменение в готовом доме. Определи точную локацию, затрагиваемые конструкции, скрытые трассы, инженерные системы и оборудование. Проверь проектные документы и историю изменений. Отсутствие сведений не считай доказательством безопасности. Предложи варианты решения, необходимые обследования, безопасную последовательность, задание подрядчику и критерии приёмки.
```

## Что продукт может

- сохранять проверяемую историю документов, решений и изменений;
- выявлять противоречия, пропуски, риски и вопросы;
- проверять КП, сметы, спецификации и договорные условия;
- предлагать технические, закупочные и подрядные альтернативы;
- искать актуальные решения, цены, поставщиков и подрядчиков со ссылками;
- готовить технические задания, запросы цены, планы работ и приёмки;
- проверять проектные решения, КП, задания и выполненные работы по точным нормативным требованиям с указанием применимости и доказательств;
- поддерживать модель готового объекта и историю оборудования;
- отделять подтверждённые факты от предположений, рекомендаций и неизвестных данных.

## Что продукт не может и не должен делать

- заменять обязательный проект, авторский или технический надзор, экспертизу, обследование и заключение профильного специалиста;
- подтверждать фактическое состояние объекта без осмотра, измерений или надёжных доказательств;
- считать отсутствие записи о скрытой трассе доказательством её отсутствия;
- придумывать недостающие размеры, объёмы, характеристики, цены или решения владельца;
- автоматически считать документ утверждённым или включать его в принятую базовую линию;
- автоматически считать изменившуюся нормативную страницу новой применимой редакцией или переписывать прежнее заключение;
- гарантировать актуальность внешней цены, наличие товара или готовность подрядчика без проверки на указанную дату и в указанном регионе;
- подписывать договоры, оплачивать счета, связываться с подрядчиками или принимать решения за владельца;
- хранить пользовательские проекты в облачной базе плагина: данные остаются в отдельных папках пользователей;
- гарантировать одинаковое качество результата при нечитаемых файлах, неполных исходных данных или ограничениях используемой модели и доступных инструментов.

## Как получить более качественный результат

- сообщайте роль, статус, дату и версию каждого документа;
- указывайте объект, помещение, систему и этап, к которым относится вопрос;
- прикладывайте не только КП, но и связанные проекты, спецификации, договоры, акты, фотографии и переписку;
- уточняйте регион, валюту, дату цен и допустимый бюджет;
- подтверждайте базовую линию только после просмотра предложенного состава и конфликтов;
- просите отделять документальные выводы от того, что требует осмотра и измерений;
- не просите «просто дать ответ»: просите показать источники, неизвестные данные, альтернативы и условия применимости;
- после обновления плагина начинайте новую задачу Codex или перезагружайте плагины Claude Code.

## Приватность

Не добавляйте документы своего дома, адреса, фотографии, договоры и данные `.home-control` в публичный репозиторий плагина. Они должны находиться только в отдельной локальной папке пользовательского проекта.

При внешнем поиске продукт должен исключать ненужные персональные и проектные данные. Пользователь проверяет, какие сведения допустимо передавать внешним источникам.

## Если что-то пошло не так

1. Убедитесь, что открыта папка пользовательского проекта, а не репозиторий плагина.
2. После установки или обновления начните новую задачу Codex либо перезагрузите плагины Claude Code.
3. Попросите: «Проверь текущую папку и состояние проекта, ничего не исправляй без предварительного плана».
4. Не удаляйте `.home-control` и не редактируйте её реестры вручную до выяснения причины.
5. Сообщите об ошибке по правилам [SUPPORT.md](SUPPORT.md), не прикладывая приватные документы к публичной задаче GitHub.
