# Контроль дома

`home-project-control` — локальный плагин для Codex и Claude Code, предназначенный для доказательного управления строительством, ремонтом и дальнейшей эксплуатацией физических объектов и установленного оборудования. Он хранит проектные данные в отдельной папке пользователя, связывает выводы с точными источниками и не изменяет оригиналы документов.

**Для первого знакомства:** [руководство пользователя](USER_GUIDE.md) объясняет, что это за продукт, как его установить и обновлять, какие задачи ставить, по какой логике он работает и где проходят границы его возможностей.

## Установка в Codex

```text
codex plugin marketplace add DmitriyVOstapenko/home-project-control --ref main
codex plugin add home-project-control@home-project-control-marketplace
```

После установки начните новую задачу Codex.

## Установка в Claude Code

```text
claude plugin marketplace add https://github.com/DmitriyVOstapenko/home-project-control.git
claude plugin install home-project-control@home-project-control-marketplace
```

После установки начните новую сессию Claude Code или выполните `/reload-plugins`, если установщик предложил это. Скиллы доступны автоматически и вручную в пространстве имён `/home-project-control:<имя-скилла>`. Подробный маршрут, вариант с локальным клонированием, обновление и удаление описаны в [INSTALL.md](INSTALL.md).

## Что делает плагин

- проверяет, что работа ведётся в отдельной подготовленной папке проекта;
- индексирует версии файлов по SHA-256;
- принимает разнородный пакет прикреплённых и внешних документов по одному общему плану и одному подтверждению, сохраняя его как `DocumentIntakeBatch`;
- независимо инвентаризирует страницы, листы и другие единицы файла, затем ведёт формальный чек-лист полного чтения и Markdown-конспект каждой версии;
- отдельно подтверждает смысловое извлечение атомарных фактов, требований, конфликтов и пробелов по каждому разделу документа;
- ведёт отдельные версионируемые слои «как есть», «что принято сделать» и «что предлагается»;
- сохраняет вопросы и поручения как возобновляемые `AnalysisRequest`, чтобы после новых данных не повторять исходную задачу;
- формирует компактную карточку объекта, открытых пробелов, незавершённых запросов и следующего действия;
- связывает один оригинал с несколькими дисциплинами и пакетами проекта без дублирования файла;
- ведёт формальный журнал недостающих данных и пересчитывает только зависимые выводы;
- проверяет пакеты ОВиК, электрики, планировки и других направлений на конкуренцию за мощность, место, трассы, конструктив, сеть, доступ и время;
- отделяет утверждённую базовую линию от коммерческих предложений;
- перед первым анализом КП показывает владельцу полностью прочитанные кандидаты, их версии, роль, область действия и конфликты, а после выбора создаёт версионный снимок базовой линии;
- проверяет любое КП — работы, материалы, оборудование, поставку, обслуживание или смешанный состав — по одному или нескольким профессиональным профилям;
- раскладывает КП на строки, двусторонне связывает их с утверждёнными требованиями и не оставляет строку либо требование без явной классификации;
- проверяет арифметику, полноту, исключения, нормы и условия оплаты;
- определяет применимые ГОСТ, СП, СНиП, ПУЭ и иные требования по официальным источникам, извлекает точные пункты и отдельно фиксирует статус документа, применимость и результат проверки;
- еженедельно отслеживает изменения стартовых официальных нормативных источников через GitHub Actions, но не меняет применимость и прежние заключения автоматически;
- даёт прорабскую оценку границ ответственности, исполнимости на объекте, полной денежной экспозиции, подрядчика, приёмки и приоритетных рисков;
- исследует оборудование, цены, отзывы и сопоставимые альтернативы со ссылками;
- при анализе КП ищет альтернативных подрядчиков и готовит единый запрос цены;
- сохраняет формулы и исходные данные расчётов, параметры внешнего поиска и проверку исключения ненужных приватных данных;
- формирует короткую карточку решения владельца, тот же канонический блок в начале полного досье и нейтральный запрос подрядчику;
- контролирует договоры, изменения, приёмку, закупки, прогресс и расходы;
- описывает один или несколько объектов, их зоны, конструкции, системы и установленное оборудование;
- ведёт историю ввода в эксплуатацию, обслуживания, отказов, ремонтов, модернизаций и замен;
- помогает проверить локальное вмешательство в готовый объект и сравнить продолжение эксплуатации, ремонт, модернизацию и замену;
- при подборе замены проверяет совместимость, простой, монтаж, пусконаладку, поддержку, поставщиков, подрядчиков и стоимость жизненного цикла.

## Как устроена работа

Плагин и пользовательский проект разделены:

1. пользователь один раз устанавливает плагин из публичного GitHub marketplace либо из локальной клонированной копии;
2. для конкретного дома, квартиры, ремонта или группы связанных локаций создаёт отдельную папку и открывает её как рабочую папку проекта в Codex или Claude Code;
3. плагин проверяет папку штатной Python-утилитой;
4. после подтверждённого предварительного просмотра создаёт в ней служебную структуру;
5. все конспекты, реестры и отчёты остаются локально внутри `.home-control`.

Один установленный плагин может работать с несколькими проектами. Репозиторий исходников не является папкой проекта.

## Архитектура

- `.agents/plugins/marketplace.json` — marketplace Codex;
- `.claude-plugin/marketplace.json` — marketplace Claude Code;
- `plugins/home-project-control/.codex-plugin/plugin.json` — manifest Codex;
- `plugins/home-project-control/.claude-plugin/plugin.json` — manifest Claude Code;
- `plugins/home-project-control/skills/` — 14 профильных скиллов;
- `plugins/home-project-control/schemas/ontology.json` — общая онтология;
- `plugins/home-project-control/schemas/project-structure.json` — эталон локальной структуры проекта;
- `plugins/home-project-control/references/` — общие протоколы рабочей папки, чтения и классификации данных;
- `tests/` — поведенческие проверки безопасного создания, проверки и миграции проекта.

Плагин работает как набор скиллов и локальных Python-утилит. MCP-сервер, HTML-формы и файл `Установить Контроль дома.cmd` не используются.

## Первый запуск

После установки откройте отдельную папку проекта в новой задаче Codex или сессии Claude Code и напишите:

```text
Начинаем новый проект.
```

Плагин проверит папку и попросит только то, чего нельзя определить из среды. Документы можно прикрепить сразу, даже до подробного описания объекта:

```text
Добавляю документы по объекту. Предложи единый план их раскладки, чтения и служебных записей. После моего подтверждения выполни весь показанный пакет.
```

Чтобы возобновить работу, достаточно написать: «Что ты уже знаешь об объекте и что делать дальше?» или «Продолжи незавершённый запрос после новых документов».

Для действующего объекта или оборудования:

```text
Помоги с эксплуатационной задачей. Сначала установи точную локацию, затрагиваемые конструкции, системы и оборудование, проверь историю и неизвестные данные, затем сравни безопасные варианты решения.
```

Для проверки любого коммерческого предложения прикрепите файл и напишите:

```text
Проанализируй это КП полностью по всем возможностям продукта. Используй состояние «как есть» и принятую базовую линию, а если их недостаточно — выполни независимые проверки и явно отдели ограничения. Дай короткую карточку решения и полное профессиональное досье с альтернативными техническими решениями, подрядчиками, ценами, нормативной проверкой и следующими действиями. Перед записью покажи единый пакет изменений.
```

## Приватность и границы применения

- Пользовательские документы, адреса, фотографии и содержимое `.home-control` должны оставаться в отдельных локальных папках проектов и не добавляться в этот репозиторий.
- При внешнем поиске плагин должен исключать ненужные данные объекта и сохранять источники, дату и регион проверки.
- Результат плагина не заменяет обязательный проект, осмотр, инструментальные измерения, расчёт или заключение профильного специалиста.
- Перед использованием результата для договора, оплаты, вмешательства в конструкции или инженерные системы владелец проверяет отмеченные ограничения и обязательные подтверждения.

Поддержка и правила безопасного сообщения об ошибках описаны в [SUPPORT.md](SUPPORT.md).
