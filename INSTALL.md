# Установка «Контроля дома»

## Установка из GitHub

Пока репозиторий закрыт, скачивание и установка доступны владельцу и приглашённым участникам. Для пользователя без команд предназначен файл `Установить Контроль дома.cmd` из раздела **Releases**.

Для разработки клонируйте репозиторий, добавьте его корневую папку как каталог плагинов и установите `home-project-control` из каталога `home-project-control-marketplace`.

## Простой вариант для Windows

Получателю нужен один файл:

`Установить Контроль дома.cmd`

1. Дважды щёлкните по файлу.
2. Установщик проверит свою целостность, распакует плагин в постоянную локальную папку и добавит его каталог в Codex.
3. Codex откроет карточку «Контроль дома». Нажмите **Установить** — это обязательное подтверждение безопасности внутри Codex.
4. После установки создайте новую задачу, чтобы загрузились скиллы.

Администраторские права, пароль, ключ API и облачные подключения не требуются.

Windows может предупредить о запуске неподписанного файла. Для распространения без такого предупреждения понадобится цифровая подпись установщика либо публикация плагина в официальном каталоге.

## Архив для разработчика

`home-project-control-marketplace.zip` содержит исходную структуру локального каталога, все 12 скиллов и локальный модуль интерактивных форм. Этот архив нужен для проверки и дальнейшей разработки; обычному пользователю достаточно файла-установщика.

## Автоматическая стартовая проверка

При первом обращении в новой задаче плагин сам проверяет текущую рабочую папку. Пользователю не нужно отвечать, создан ли проект. Проверяются:

- карточка `.home-control/project.json`;
- привязка абсолютного пути;
- обязательные проектные папки;
- наличие и базовый формат служебных JSON, JSONL и CSV-файлов.

Если ранее созданный проект полностью исправен, работа продолжается без стартовой формы. Если проект не найден, структура неполна или выбрана неподходящая папка, открывается визуальный мастер. В нём можно выбрать папку существующего проекта, создать новый проект с названием и путём либо восстановить только недостающие элементы текущего проекта.

Эта проверка подтверждает рабочую папку, доступную Codex. Она не может независимо подтвердить название или принадлежность отдельного визуального контейнера **«Проект»** в интерфейсе ChatGPT, если клиент не передал эти сведения плагину.

Нажатие **«Создать проект»** или **«Восстановить структуру»** подтверждает соответствующую неразрушающую операцию. Перед записью плагин выполняет сухую проверку; существующие документы не удаляются и не перезаписываются. Повреждённые существующие служебные файлы автоматически не заменяются.

## Основная интерактивная анкета

После успешной стартовой проверки проводник открывает основную форму внутри разговора. В ней можно переключателями выбрать один вариант, а галочками — несколько систем, видов работ и документов. Для последующих закрытых вопросов в плагин также встроена универсальная форма выбора. Текст остаётся только для уникальных сведений, например названия объекта, местоположения или важного ограничения.

Нажатие **«Передать ответы в чат»** проверяет ответы и возвращает их проводнику. Оно не создаёт папку и не записывает проектные файлы.

Если используемая версия клиента не отображает MCP Apps, проводник автоматически продолжает теми же вопросами в текстовом режиме.

## Первая проверка

В новой задаче можно написать:

```text
Веди меня пошагово по новому проекту дома. Задавай вопросы небольшими блоками и помоги создать папку проекта, когда мы определим исходные данные.
```

Проводник сначала автоматически проверит текущую папку. Для исправного существующего проекта он продолжит работу сразу; для первого запуска откроет мастер выбора или создания проекта. После создания появится основная интерактивная анкета.

Затем поместите копию коммерческого предложения в папку проекта и попросите:

```text
Проиндексируй документы проекта и проверь коммерческое предложение. Отдели факты документа от внешних данных и неизвестных параметров.
```
